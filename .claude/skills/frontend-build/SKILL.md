# Frontend Build

## Purpose
Implement one plan phase, task or review fix so that it matches `DESIGN.md`, renders only `info.md`-derived content, and passes the verification gate before anyone reviews it.

## When to Use
- Executing an approved plan phase or task.
- Fixing `qa-reviewer` or `design-lead` findings.
- A small change the main session has approved.

## Inputs
- The phase or task brief (tasks, acceptance criteria, file map entries)
- `DESIGN.md`, content files and `info.md`
- `CLAUDE.md`, and any findings to fix

## Responsibilities
- Technical decisions inside the plan's boundaries: implementation, the task's own checks, a self-check, and an honest report.
- Not in scope: changing `DESIGN.md` or `info.md` (request it through the main session), inventing content, approving your own work.

## Workflow
1. Read the brief, the `DESIGN.md` sections it touches, and the code it extends. List the files you will create or modify.
2. Before any import, confirm the package is in `package.json`. Add only dependencies the plan allows, after checking the current version and licence with `npm view`.
3. **Define the checks first:**
   - unit tests that fail first for logic (content schema, utilities, metadata and JSON-LD builders, state logic)
   - Playwright + axe assertions for UI: renders, landmarks and headings, keyboard path, no horizontal overflow at 320px, both themes
4. **Build server-first.** Pages are static. Server Components are the default. Client components are small leaves (theme toggle, menu, a motion island) that receive minimal serialisable props.
5. **Style with tokens only:**
   - use the CSS generated by `npx @google/design.md export --format css-tailwind DESIGN.md`, plus the thin dark-theme mapping layer
   - mobile-first, following DESIGN.md's per-section collapse
   - `min-h-dvh`, never `h-screen`; grid for two-dimensional layout
6. **Build accessibility in as you go:**
   - landmarks, one `h1`, ordered headings, skip link
   - real `<a>` and `<button>` elements, labels, meaningful `alt`
   - visible `:focus-visible`, hit areas ≥ 44px
7. **Motion follows DESIGN.md's budget:**
   - transform and opacity only
   - transitions list their properties explicitly (never `all`)
   - interruptible, with a reduced-motion variant
   - `motion/react` only inside client leaves
   - no scroll event listeners (use IntersectionObserver, CSS scroll-driven animation, or `useScroll`)
   - effects clean up
8. **Content** comes from the typed content files only. An absent optional field means the element is not rendered.
9. Run the `verification` skill. Capture 375 / 768 / 1440 px in light and dark, and compare against `DESIGN.md` yourself.
10. Report (see Expected Output).

### Fixing findings
For each finding: verify it against the code first. Fix Critical and Important findings. Fix a Minor one if cheap; otherwise list it. If a finding is wrong, push back with evidence (test, screenshot, spec line). If any item is unclear, ask before changing anything. Re-run the full gate afterwards.

## Rules
- **React / Next.js** (Vercel):
  - no barrel files
  - `next/dynamic` for heavy client-only code
  - defer third-party scripts, or drop them
  - hoist static data and I/O to module level
  - keep props to client components small
  - no components defined inside components
  - derive state during render instead of syncing it in effects
  - ternaries rather than `&&` for conditional JSX that can be `0`
  - a hydration-safe theme script, so there is no flash
  - resource hints only for critical assets
- **Composition:** explicit variant components instead of boolean props, children instead of render props, compound components only when parts share state, no `forwardRef` (React 19).
- **Media:** the framework image component with explicit dimensions and modern formats. Only the LCP image gets `priority`; the rest lazy-load. Fonts are self-hosted and subset, with `display: swap`, and only critical fonts are preloaded.
- **CSS:**
  - no raw colours, sizes, radii, shadows or durations outside tokens
  - z-index only from the named scale
  - watch selector specificity so section spacing rules don't cancel each other
- **Icons** come only from the library named in `DESIGN.md`. No hand-drawn SVG icons.
- **Typography:** `…`, curly quotes, `&nbsp;` for units and brand names, `tabular-nums` for aligned numbers, `text-wrap: balance` on headings.
- Never weaken, skip or delete a test or lint rule to get green. Report the conflict instead.
- Stay in scope (YAGNI). Put ideas in the report instead of the code. Do not spawn subagents.
- Servers and processes you start (dev, start, preview, screenshot servers) are stopped by their PID only. Never `pkill`, `killall` or pattern-kill: other projects on the owner's machine may be running.

## Expected Output
Code and tests, plus a report:

- **Status:** `DONE` | `DONE_WITH_CONCERNS` | `NEEDS_CONTEXT` | `BLOCKED`
- files changed
- checks run (command → result line)
- screenshot paths
- deviations from the brief, with the reason for each
- open questions and concerns

## Verification / Definition of Done
- The `verification` gate passes, with the evidence quoted in the report.
- Every acceptance criterion is checked and has evidence.
- No token violations, no hardcoded personal facts, no console errors or hydration warnings.
